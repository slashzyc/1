# 比赛要求与验收映射

| 要求 | 实现入口 | 验收方法 |
|---|---|---|
| 真实业务场景 | 四类客服，首例家居外贸美国／德国 | 查看产品计划与工作台 |
| 中文／目标语言输入，至少两种语言 | 英文＋德文双语结构 | 生成后检查两栏内容 |
| 至少两轮对话式迭代 | 继续迭代、V1/V2/V3、前后对比 | 连续修改两次；数据库保留三版 |
| 至少两个平台或场景 | Alibaba RFQ、Amazon Listing、售后邮件 | 同商品从询盘转上架；售后转人工 |
| 平台本地化 | RFQ商务语气，Listing标题／亮点／卖点 | 查看目标市场单位、语言与规则 |
| 两类以上校验 | 平台、合规、表达、合同内控 | 测试食品级／环保、长标题、MOQ、交期 |
| 两种以上反馈 | 风险标记＋文本批注＋版本对比 | 打开相应标签 |
| 智能体与能力配置 | config/agents.json，规则检索和服务端模型 | 设置页导出配置；查看真实调用标识 |
| 现场可重复闭环 | 离线确定性模式＋真实模型模式 | `node scripts/demo.mjs`；`--live`单独验收 |
| 至少两个相关工作流 | 询盘→商品上架；售后→人工接管 | sourceRunId与商品快照；工单记录 |
| 数据传递与异常处理 | docs/API.md、架构图、错误码 | 超时／余额／401／格式错误不会伪造成功 |
| 批量生成（加分） | Listing批量1–5商品 | 每项独立结果；部分失败清晰返回 |
| 工程与README | Node24完整工程、零运行时依赖 | check、test、build |
| 第三方声明 | THIRD_PARTY_NOTICES.md | 审查依赖与数据授权 |
| 海报 | 800×1800mm PDF | pdfinfo物理尺寸、渲染视觉检查 |
| 3分钟展示 | 自包含HTML＋讲稿 | 双击HTML、左右键、计时、讲稿模式 |
| GitHub与Tag | 用户仓库、hackathon-final | 推送后对比远端commit／tag |

“真实模型已验收”只以最终 docs/evidence/live-verification.json 中 status=passed 且存在上游responseId为准。自动测试使用Mock的部分不作为真实调用证据。已实现能力与商用待办在 README 明确区分。

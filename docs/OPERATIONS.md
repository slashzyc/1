# 运维与商业化推进

1. 使用 Node.js 24。默认零依赖启动；文件写入目录须有权限。首次运行会创建示例台账和 SQLite schema version 1。
2. 主机本地试点采用回环监听。远程访问配置长随机 APP_TOKEN、APP_ORIGIN 和 HTTPS 反向代理；网关增加按身份的限流与监控。当前应用按连接地址限流，不信任任意 X-Forwarded-For。
3. 模型超时默认60秒，可设 MODEL_TIMEOUT_MS（1–120秒）。最多2次上游尝试，包含格式错误重试。批量串行处理最多5个商品，部分失败不抹掉成功项，现场用离线模式演示批量以减少网络不确定性。
4. `/readyz` 检查数据库；采集错误码、请求ID、生成延迟、失败率与上游Token，不记录密钥、完整客户文本或原始模型错误。当前日志是最小实现，没有内置监控平台。
5. 备份：停止应用，复制完整 `data/`（包括可能存在的 WAL/SHM 文件），保存到有访问控制的加密备份位置；用副本在隔离环境恢复并检查历史版本。不要在服务写入时只复制 sqlite 主文件。此交付已测试数据库重新打开，尚未在生产设施演练灾难恢复。
6. 删除／迁移：先备份与确认保留政策；本项目不自动删除任何真实资料。工单解决不会删除任务。数据保留、主体请求、法律依据和供应商协议由部署方定义。
7. 规则更新：复核官方原文，修改 knowledge/rules.json 的摘要、版本与复核日期，并添加回归测试。不要把平台登录后专有文档未经授权公开。旧任务保留旧规则快照，便于复盘。
8. 升级：停机备份→运行新版本测试→启动→验证健康和一条离线任务。当前仅有首次建表逻辑；后续 schema 变更须实现显式迁移，不能直接假设兼容。

## 商业化分阶段

已实现：四类客服、共享事实、真实模型适配器、双语产出、两轮修改、批量、独立规则检查、人工队列、导出、持久化、测试与CI。

试点期：邀请3家商家，每家20个历史询盘做盲测，记录人工首稿时间、AI辅助时间、采用率、事实错误、风险漏检与成本；不预填“提升XX%”。核实数据授权，安排英德语言审校。将工作区与模型调用成本分开核算，定价待实测。

多人商用前：SSO、岗位权限、多租户隔离、审计不可篡改策略、监控告警、备份恢复演练、合规规则维护责任、用量配额／账单、数据处理协议、可访问性检查、部署安全审计。真实订单／平台连接按官方授权API逐个添加，禁止通过违规爬取补功能。

## 已知限制

启发式规则会误报／漏报；格式校验不能证明事实真实。没有信用背调、证书真实性核验、实时物流、退款执行或平台发布功能。德国市场安全信息字段齐全也不等于通过GPSR。商品中文名称之外的多语言字段由商家提供，演示模板不会自动翻译新商品。人工队列不提供站外通知或独立员工身份。无语音与出图（比赛可选项）。

# 出海智台 HarborFlow · 产品与开发计划

版本：1.0 · 2026-10-21 · 开发前基线

用户确认后调整：产品为多方向 AI 客服工作台，包含销售顾问、售后专员、上架运营、合规顾问与人工接管工单。家居用品作为验收数据；其他普通商品可以通过符合 schema 的中英德商品 JSON 接入，但新行业规则覆盖必须另行评估。模型服务选定 DeepSeek 官方，真实调用的验收结果以最终测试报告为准。

## 产品定位

服务 5–30 人规模的家居收纳用品出口团队。以经商家授权的商品台账和询盘文本为输入，帮助业务员完成英文／德文询盘与报价草稿，再把同一商品事实传给运营生成 Amazon 上架草稿。合规岗位看到可追溯规则、风险与缺失材料。目标市场为美国、德国；首版只处理普通非电气、非食品接触、非儿童用品。买家信息仅提取用户提供的文本，不声称完成企业信用背调。

## 业务闭环

1. 业务员选择商品、市场和结构化商务条件，粘贴中文或目标语言需求。
2. 服务端校验输入，读取商品快照，按市场／场景检索有来源和复核日期的规则。
3. 生成双语询盘回复与跟进计划，金额由程序按整数分计算，模型不可修改报价表。
4. 独立规则引擎检查输入、输出与事实缺口，用风险标记、文本批注、版本对比反馈。
5. 用户连续修改两轮；每轮保留输入、输出、规则版本、耗时、模型来源和审计记录。
6. 从询盘一键转入 Listing 工作流，复用商品与市场，生成标题、Item Highlights、卖点和运营交接；支持多商品批量。
7. 导出带风险和来源的草稿包，由人员在目标平台核实并提交。

## 实现边界与商业标准

首版为可独立部署的单租户试点产品，不宣称已具备多租户 SaaS 的商业运营能力。不内置虚构转化率、客户证言或“全面合规”结论；不自动向买家发送消息，不模拟已经上架。使用明确标注的合成商品数据。离线演示是确定性本地模板；真实 AI 模式通过服务端 OpenAI 兼容 Chat Completions API 调用，必须配置密钥和模型。无密钥时不能满足“真实大模型调用已验证”，交付验收应明确标为待完成。

稳定性：无运行时第三方 npm 依赖，Node.js 24 LTS + 原生 HTTP + SQLite + 原生浏览器模块。持久化交易、修订冲突保护、输入限制、超时、可重试错误、失败不冒充成功、数据库健康检查、自动化测试、CI、Docker 非 root 运行。数据访问默认仅本机；非回环监听强制配置访问口令，反向代理负责 TLS。口令是单工作区边界，并非 RBAC。上线多人使用前需完成 SSO／岗位权限、备份演练、监控、隐私与供应商合同评审。

## 开发顺序与完成门槛

| 阶段 | 交付 | 门槛 |
|---|---|---|
| 1 设计 | 本文、来源与规则配置、数据模型 | 每项比赛要求有对应入口 |
| 2 核心 | 商品、检索、生成、校验、修订、导出 | 规则与金额单测；API 集成测试 |
| 3 界面 | 工作台、双语草稿、合规、知识库、历史、设置 | 浏览器走完两个工作流和两轮修订 |
| 4 可靠性 | 安全边界、限流、错误处理、批量、持久化 | 异常路径和并发冲突测试 |
| 5 交付 | README、配置导出、声明、海报、3 分钟 HTML 路演、工程 ZIP | PDF 视觉检查、可重复演示脚本、完整工程 |
| 6 发布 | GitHub 源码与 hackathon-final 标签 | 推送后核对远端 SHA；无密钥和运行数据 |

## 数据与调用契约

浏览器 → REST API → 输入校验 → SQLite 商品事实／知识库 → 本地模板或外部模型 → 严格输出结构校验 → 独立规则引擎 → 原子写入版本／审计 → 浏览器预览与草稿导出。只向模型发送本次必要的商品、需求、规则和历史文稿。API 密钥始终留在服务端环境变量。模型供应商接收的内容可能含商业信息，真实部署前需确认授权。

## 价值验证计划

与至少 3 家商家各抽取 20 个历史询盘，比较人工基线与辅助流程的首稿时间、修改次数、事实错误、风险漏检和实际采用率。首版不填入未测得的节省比例或收入数据。试点收费可按工作区与用量设计，须待成本／采用率测量后定价。
